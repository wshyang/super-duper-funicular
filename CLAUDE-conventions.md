# GREENFIELD §6 — conventions that prevent whole classes of bugs

## `data-testid` on every interactive element

Naming convention: `{component-kebab}__{element-role}`, applied at authoring time, never retrofitted.

| Element | testid |
| --- | --- |
| Stage canvas | `stage__canvas` |
| Controls panel | `controls__panel` |
| A gait slider | `controls__slider-cadence` (one per control key) |
| A kit swatch | `controls__swatch-red` |
| A display toggle | `controls__toggle-showSkeleton` |
| Play/pause | `controls__play` |
| Playback speed | `controls__speed` |
| Metrics panel | `metrics__panel` |
| A metric value | `metrics__value-speed` |
| Flaw panel | `flaws__panel` |
| Parts atlas panel | `atlas__panel` |
| A part canvas | `atlas__canvas-thigh` |
| Reference strip | `reference__panel` |

Repeated elements share one testid (the seven atlas canvases are one per part id, which is the anchor);
scope by the id suffix rather than inventing new names.

## Typed boundaries

- The only wire boundary is `public/sprites/manifest.json` and `src/generated/reference-analysis.json`.
  Both are generated, both are typed at the import site (`ReferenceStrip` and `flaw-panel.ts`), and both
  are regenerated by a script in the same commit as any change to their shape.
- `manifest.json` is consumed through the `Manifest` interface in `src/app/components/reference-strip.ts`.
  Renaming a field there is a compile error, not a silent `undefined`.

## Copy rules

- User-facing copy describes the animation, never the internal decisions. The flaw panel states measured
  facts ("2 of 8 frames touch the ground"), not design rationale — the rationale lives in
  `docs/sprite-flaw-analysis.md` and `docs/ADDENDA.md`.
- No internal slugs, addendum numbers, or file paths in UI text.
- Party/third-party contract keys (here: the manifest and analysis JSON) keep their exact spelling even
  when it disagrees with local naming.

## Practical impact

- Adding an interactive element without a `data-testid` is a review failure.
- Adding a manifest field means updating the interface, the extractor, and the docs together.
